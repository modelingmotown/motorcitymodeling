In SPSS, “Exploratories” (more properly the **Explore** procedure, invoked via the **EXAMINE** command) is your one-stop exploratory data analysis tool.  It will, for each variable (and optionally by group), produce:

* **Descriptive statistics** (N, mean, SD, min, max, quartiles)
* **Distribution plots** (histograms, stem-and-leaf, boxplots)
* **Normality tests** (e.g. Shapiro–Wilk)
* **Outlier indicators** (via boxplot whiskers)
* **Confidence intervals** for means, etc. ([ibm.com][1])

A typical SPSS syntax snippet looks like:

```spss
EXAMINE VARIABLES=priceclass BY sresb_style
  /PLOT=BOXPLOT STEMLEAF HISTOGRAM
  /STATISTICS=DESCRIPTIVES
  /CINTERVAL=95
  /MISSING=PAIRWISE.
```

---

### R equivalents

There isn’t a single base-R command that does absolutely everything in one go, but you can compose the same steps very easily:

```r
# assuming your data.frame is df

# 1. Descriptive stats
summary(df$priceclass)

# or, for a more complete table:
# install.packages("psych")
psych::describe(df$priceclass)

# 2. Grouped summaries
# install.packages("dplyr")
library(dplyr)
df %>%
  group_by(sresb_style) %>%
  summarise(
    N      = n(),
    Mean   = mean(priceclass, na.rm=TRUE),
    SD     = sd(priceclass,   na.rm=TRUE),
    Median = median(priceclass,na.rm=TRUE),
    IQR    = IQR(priceclass,  na.rm=TRUE),
    Min    = min(priceclass,   na.rm=TRUE),
    Max    = max(priceclass,   na.rm=TRUE)
  )

# 3. Plots
hist(df$priceclass)                              # histogram
stem(df$priceclass)                              # stem-and-leaf
boxplot(priceclass ~ sresb_style, data = df)     # boxplot by group

# 4. Normality test
shapiro.test(df$priceclass)

# 5. Automated EDA reports (all in one)
# install.packages(c("skimr","DataExplorer","summarytools"))
skimr::skim(df)
DataExplorer::create_report(df)
summarytools::dfSummary(df)
```

With these pieces you replicate SPSS’s Explore output in R—either piecemeal with base functions or in one fell swoop with an EDA package.

[1]: https://www.ibm.com/docs/SSLVMB_sub/statistics_reference_project_ddita/spss/base/syn_examine.html?utm_source=chatgpt.com "EXAMINE - IBM"

To reduce vertical length and **fit more columns horizontally** in an **HTML output** from R Markdown, here are several effective techniques:

---

## ✅ 1. **Use `kable()` or `datatable()` with horizontal scroll**

### a) `knitr::kable()` + scrollable wrapper

```r
library(knitr)

# Wrap your kable in a div with overflow-x: auto
cat("<div style='overflow-x:auto;'>")
kable(your_dataframe)
cat("</div>")
```

This lets the table scroll horizontally rather than wrap or stack vertically.

---

### b) `DT::datatable()` (best for interactivity + scrollbars)

```r
library(DT)

datatable(
  your_dataframe,
  options = list(scrollX = TRUE)
)
```

This produces a slick, scrollable, column-squishing table with sorting and search.

---

## ✅ 2. **Rotate column headers (CSS)**

If column names are wide but values are short, add this to your YAML or an inline style block:

```yaml
output: 
  html_document:
    css: styles.css
```

Then in `styles.css`:

```css
th {
  transform: rotate(-45deg);
  white-space: nowrap;
}
```

Or inline:

```html
<style>
th {
  transform: rotate(-45deg);
  white-space: nowrap;
}
</style>
```

---

## ✅ 3. **Set a smaller font**

Globally in YAML:

```yaml
output:
  html_document:
    css: styles.css
```

In `styles.css`:

```css
body {
  font-size: 12px;
}
```

Or locally in a chunk:

```r
kable(df) %>%
  kableExtra::kable_styling(font_size = 10)
```

---

## ✅ 4. **Reduce margins and padding**

In `styles.css`:

```css
table {
  padding: 0;
  margin: 0;
  font-size: 12px;
  table-layout: fixed;
  width: 100%;
}
```

---

## ✅ 5. **Transpose your data (for a small number of rows)**

If you have few rows but many columns:

```r
t(df)  # transpose the dataframe
```

Then use `kable()` or `datatable()` on that.

---

### Summary

| Goal                     | Best Option                     |
| ------------------------ | ------------------------------- |
| Scrollable wide tables   | `DT::datatable(scrollX=TRUE)`   |
| Squeeze columns together | Smaller font + CSS tweaks       |
| Prevent wrapping headers | `white-space: nowrap;` in CSS   |
| Rotate headers           | `transform: rotate(...)` in CSS |
| Transpose data           | Use `t(df)`                     |

When you need a true PDF rather than an HTML “print,” you essentially have two good paths:

---

## 1. Knit straight to PDF via LaTeX (`pdf_document`)

The most reliable way is to let R Markdown generate a LaTeX‐based PDF. In your YAML header switch:

```yaml
output:
  pdf_document:
    latex_engine: xelatex    # or “pdflatex”/“lualatex” as you prefer
    keep_tex: true           # (optional) to inspect the .tex file afterwards
    toc: true                # (optional) add a table of contents
    geometry: margin=1in     # adjust page‐margins
```

Then in your chunks use LaTeX-friendly tables (via **kableExtra** or **xtable**) and dial in:

```r
library(kableExtra)

kable(df, format = "latex", booktabs = TRUE) %>%
  kable_styling(
    latex_options = c("hold_position", "scale_down")  # auto‐scale wide tables
  )
```

### Tips for PDF tables

* **`scale_down`** will shrink your table to fit the page width.
* If you need **landscape** pages, wrap the table in a LaTeX environment:

  ```r
  cat("\\begin{landscape}")
  kable(...) %>% …
  cat("\\end{landscape}")
  ```
* Use `header_includes` in YAML to load packages, e.g.

  ```yaml
  header-includes:
    - \usepackage{pdflscape}
    - \usepackage{booktabs}
    - \usepackage{tabularx}
  ```

That approach gives you full control over page size, fonts, margins, and reliably handles multi‐page tables (via `longtable` or `tabularx`).

---

## 2. Convert your HTML to PDF with a headless browser

If you’ve already styled everything in your **html\_document** (with scrollable divs, CSS tweaks, etc.) and want a quick “print‐to‐PDF”:

### a) **pagedown** (recommended)

```r
# Install if needed
# install.packages("pagedown")

pagedown::chrome_print(
  input  = "report.html",
  output = "report.pdf",
  format = "A4"      # or "Letter"
)
```

This uses Headless Chrome to render your HTML (including any CSS) and “print” it to PDF.

### b) **webshot2**

```r
# install.packages("webshot2")
webshot2::webshot(
  url    = "report.html",
  file   = "report.pdf",
  delay  = 0.5,      # wait for JS/CSS
  zoom   = 1.2,
  vwidth = 992       # viewport width
)
```

---

### Which to choose?

| Need…                                                            | Use…                        |
| ---------------------------------------------------------------- | --------------------------- |
| Precise control (margins, fonts, page breaks), LaTeX tables, TOC | **pdf\_document** (LaTeX)   |
| “What you see in browser” → PDF (with CSS, scrollbars printed)   | **pagedown::chrome\_print** |

If you’re already comfortable tweaking LaTeX, go with **pdf\_document**. If you’ve invested in HTML+CSS styling and just want a faithful printout, **pagedown** is your quickest route.

Great question! To analyze the distribution of **standardized residuals** using a frequency histogram and a smooth curve, you'll typically do the following in **R**:

---

## ✅ 1. Fit your model and extract standardized residuals

Assuming a linear model:

```r
model <- lm(y ~ x1 + x2, data = df)

# Standardized residuals (Z-score like)
std_resid <- rstandard(model)
```

---

## ✅ 2. Create a histogram with a normal curve overlay

```r
hist(std_resid, 
     breaks = 20, 
     freq = FALSE,   # plot density, not counts
     col = "lightblue", 
     main = "Histogram of Standardized Residuals",
     xlab = "Standardized Residuals")

# Add a normal curve (mean = 0, sd = 1)
curve(dnorm(x, mean = 0, sd = 1), 
      col = "red", 
      lwd = 2, 
      add = TRUE)
```

This shows whether your residuals are approximately normal — a core assumption of many linear models.

---

## ✅ 3. (Optional) Add kernel density estimate (your data's own shape)

```r
lines(density(std_resid), col = "darkgreen", lwd = 2)
legend("topright", legend = c("Normal Curve", "KDE"),
       col = c("red", "darkgreen"), lwd = 2)
```

This helps compare the theoretical normal curve to the **actual distribution** of your residuals.

---

### Summary:

| Step           | Function                        |
| -------------- | ------------------------------- |
| Get residuals  | `rstandard()` or `resid()`      |
| Histogram      | `hist(..., freq = FALSE)`       |
| Normal curve   | `curve(dnorm(...), add = TRUE)` |
| KDE (optional) | `lines(density(...))`           |

Here’s a systematic checklist for chasing down why your R lm() coefficients (and related stats) don’t match SPSS:

---

## 1. Verify you’re using the *exact* same data

1. **Row count**

   ```r
   nrow(df)                # total rows in R
   nobs(lm_model)          # rows used in the regression
   ```

   Compare with “N” in the SPSS regression output.
2. **Missingness**

   ```r
   sapply(df[, c("y","x1","x2",…)], function(v) sum(is.na(v)))
   ```

   SPSS by default does *listwise* deletion.  R’s `lm()` default `na.action=na.omit` also does listwise, but if you ever used `na.exclude` or another policy the N can differ.

---

## 2. Confirm your model spec matches SPSS’s

* **Formula**: check you’re regressing the same `y ~ x1 + x2 + …` without typos or extra interactions.
* **Weights**: did you accidentally set `weights=` in R or a weight in SPSS?
* **Transformations**: ensure any SPSS `COMPUTE log_x = LN(x)` or recodes were re-implemented identically in R before fitting.

---

## 3. Align your factor (categorical) coding

By default R uses treatment contrasts with the *first* level as the reference. SPSS’s default is also dummy coding but often uses the *last* or *lowest numeric* level as reference.

1. **Check your levels**

   ```r
   table(df$group)       # SPSS’s output will list your categories   
   levels(df$group)      # R’s ordering
   ```
2. **Re-level in R** to match SPSS’s reference category:

   ```r
   df$group <- relevel(df$group, ref = "the_SPS S_base_level")
   ```
3. **Force R’s contrasts** (if SPSS used simple 0/1 dummies):

   ```r
   options(contrasts = c("contr.treatment","contr.poly"))
   ```

   Then re-fit your model.

---

## 4. Double-check intercept handling

* R always includes an intercept by default. If SPSS used “no intercept” or you used `/NOINT` in SPSS, you must add `-1` or `0 +` to your formula in R:

```r
lm(y ~ x1 + x2 - 1, data = df)
```

---

## 5. Compare parameter estimates & std errors side-by-side

After fitting:

```r
modR <- lm(y ~ x1 + x2 + group, data = df)
library(broom)
rCoefs <- tidy(modR)                # R’s table
# Copy SPSS’s coefficients table into a data.frame spssCoefs
compare <- merge(rCoefs, spssCoefs, by="term", suffixes=c(".R",".SPSS"))
print(compare)
```

Seeing them next to each other often reveals a systematic shift (e.g. if every slope is off by a constant factor, you may have missed scaling/centering).

---

## 6. Check the fit statistics

* **R-squared**, **AIC**, **σ̂** etc.:

```r
summary(modR)$r.squared
AIC(modR)
summary(modR)$sigma
```

Compare to SPSS’s **R²**, **AIC** (you can compute AIC from SPSS’s SSE and N), and **Std. Error of the Estimate**.  If these match but your betas don’t, it’s almost certainly a contrast/data issue.

---

## 7. Turn on verbose step‐wise logs (if using `step()`)

If you’re using `step()` to select predictors in R, run with

```r
step(full_mod, direction="backward", trace=1)
```

to see exactly which terms get dropped at each iteration—and confirm you started with the same full model as SPSS.

---

### Quick summary of the most common culprits

1. **Different N** (due to missing-data handling)
2. **Mis-specified formula** (extra/missing term or intercept)
3. **Factor contrast/reference mismatch**
4. **Un-reproduced transformations** (logs, scales)
5. **Weights or case-weights** applied in one and not the other

Walk through the steps above, and you’ll reliably pinpoint where R and SPSS are diverging. Once you’ve aligned data, formula, and contrasts, the coefficients should line up exactly.

..

5. (Alternate) Use olsrr for one‐line backward p-value

If you’d rather avoid writing your own loop, the olsrr package has a function that does exactly this:

install.packages("olsrr")
library(olsrr)

# pent = p-value to stay in (PIN), prem = p-value to remove (POUT)
step_mod <- ols_step_backward_p(full_mod, 
                               pent = 0.05, 
                               prem = 0.10,
                               details = TRUE)

# The final model is in:
step_mod$model
summary(step_mod$model)

ols_step_backward_p() will print each drop (like SPSS’s trace) and return an object whose $model is your final lm.

You can wrap that three–step pipeline into a single, reusable function that takes any data frame and any one of its columns and spits back the nicely transposed, label-free table. Here’s a minimal example using tidy-eval (the `{{ }}` “curly‐curly” operator) from **rlang**/**dplyr**:

```r
library(dplyr)
library(janitor)

make_t_freq <- function(data, variable, digits = 1) {
  # data     : your data frame
  # variable : an unquoted column name in data
  # digits   : how many decimals for the percent
  
  # 1) build the basic tabyl, add % formatting and totals
  tbl <- data %>%
    tabyl({{ variable }}) %>%               # frequency table
    adorn_pct_formatting(digits = digits) %>%  # "12.3%"
    adorn_totals()                            # add a "Total" column
  
  # 2) transpose to get categories across the top
  mat <- t(tbl)
  
  # 3) blank out the auto-generated 1,2,3… column names
  colnames(mat) <- rep("", ncol(mat))
  
  # return as a matrix (prints nicely), or wrap in kable() downstream
  mat
}

# ——— Example usage ———
# Suppose your df has a column called ECF:
res <- make_t_freq(my_df, ECF, digits = 1)
print(res)
```

#### If you want to immediately render with **knitr::kable()** (say in an RMarkdown chunk):

```r
library(knitr)

make_t_freq(my_df, ECF) %>%
  kable(
    format    = "latex",   # or "html"
    booktabs  = TRUE,
    caption   = "Frequencies of ECF"
  )
```

Or, if you prefer the function itself to return a **kable** object:

```r
make_kable_freq <- function(data, variable, digits = 1, fmt = "latex", cap = NULL) {
  mat <- make_t_freq(data, {{ variable }}, digits)
  knitr::kable(mat, format = fmt, booktabs = TRUE, caption = cap)
}

# usage
make_kable_freq(my_df, ECF, cap = "ECF Frequencies")
```

With these in your script you can now call `make_t_freq(df, ANY_COLUMN)` (or the kable‐returning wrapper) on any single variable you like, and get back that same transposed, label-free table every time.

You’ve got two very common use-cases here—an image just at the top of your first page (like a logo on your title), or stamped into the header of every page. Below are recipes for both **PDF** and **HTML** outputs.

---

## 1. Image at the start of the document

### PDF or HTML

Just drop a hidden code-chunk right after your YAML:

````yaml
---
title: "My Analysis"
author: "Elliot Dean"
date: "`r format(Sys.Date(), '%-d %B %Y')`"
output:
  pdf_document: default
  # or
  # html_document: default
---

```{r logo, echo=FALSE, out.width='50%', fig.align='center'}
knitr::include_graphics("path/to/your/logo.png")
````

That will render `logo.png` centered at the very top of your report, before the title.

---

## 2. Image in the header of **every** page

### A) PDF (`pdf_document`)

1. Put your logo (say `logo.png`) in the same folder as your `.Rmd`.
2. Add these lines under your YAML’s `header-includes`:

```yaml
---
title: "My Analysis"
output:
  pdf_document:
    latex_engine: xelatex   # or pdflatex
header-includes:
  - \usepackage{graphicx}
  - \usepackage{fancyhdr}
  - \pagestyle{fancy}
  - \fancyhf{}                                % clear defaults
  - \fancyhead[L]{\includegraphics[height=1cm]{logo.png}}
  - \renewcommand{\headrulewidth}{0pt}        % remove header line
---
```

* `\fancyhead[L]{…}` places the logo flush left.
* You can also use `\fancyhead[C]{…}` or `\fancyhead[R]{…}` for center/right.
* Adjust `[height=...]` to fit your page.

Every page (including the title page) will now carry your logo in the header.

---

### B) HTML (`html_document`)

You can inject a fixed `<div>` into the `<body>` via raw HTML + CSS:

```yaml
---
title: "My Analysis"
output:
  html_document:
    css: styles.css   # optional, if you prefer an external stylesheet
---

<!-- this goes right below the YAML -->
<style>
  .fixed-header {
    position: fixed;
    top: 0; left: 0; right: 0;
    background: white;
    padding: 5px 0;
    text-align: center;
    z-index: 1000;
  }
  body { margin-top: 60px; }  /* make room for the header */
</style>

<div class="fixed-header">
  <img src="logo.png" style="height:40px;"/>
</div>
```

* `.fixed-header` will stay at the top of every screen/page when printed.
* `body { margin-top: 60px; }` ensures your content isn’t hidden underneath.
* Tweak `height`, `padding`, and `margin-top` to taste.

---

### Summary

| Where          | PDF (`pdf_document`)                         | HTML (`html_document`)                    |
| -------------- | -------------------------------------------- | ----------------------------------------- |
| **First page** | `knitr::include_graphics()` chunk after YAML | Same chunk, it works in HTML too          |
| **Every page** | `fancyhdr` in `header-includes`              | Fixed `<div>` + CSS in your document body |

Pick the approach you need, adjust paths/sizes, and you’ll have your logo front and center—or on every page.

To get your logo **above the title** (or even in the page header) you can’t just drop a code‐chunk in the body, because R Markdown always renders the YAML title *before* your first chunk. Instead you need to inject the image *into* the document template. Here are two bullet-proof ways:

---

## 1. Image at the very top (before the title)

### PDF output

1. Create a tiny LaTeX include file, say `pre_body.tex`, next to your `.Rmd` with:

   ```latex
   \begin{center}
     \includegraphics[height=1cm]{logo.png}
   \end{center}
   ```
2. In your YAML, tell `pdf_document` to include it *before* the body:

   ```yaml
   ---
   title: "My Report"
   author: "Me"
   output:
     pdf_document:
       includes:
         before_body: pre_body.tex
   ---
   ```

### HTML output

1. Create `pre_body.html` containing:

   ```html
   <div style="text-align:center;margin-bottom:1em;">
     <img src="logo.png" style="height:60px;" alt="Logo"/>
   </div>
   ```
2. In your YAML:

   ```yaml
   ---
   title: "My Report"
   author: "Me"
   output:
     html_document:
       includes:
         before_body: pre_body.html
   ---
   ```

Both of these inject your image *into* the template just **before** the title, so it truly sits at the top of page 1.

---

## 2. Image in the header of *every* page

### PDF only (using fancyhdr)

Add to your YAML:

```yaml
---
output:
  pdf_document:
    latex_engine: xelatex
    includes:
      in_header: header.tex
---
```

Then in `header.tex`:

```latex
\usepackage{graphicx}
\usepackage{fancyhdr}
\pagestyle{fancy}
\fancyhf{}                                 % clear default header/footer
\fancyhead[L]{\includegraphics[height=1cm]{logo.png}}
\renewcommand{\headrulewidth}{0pt}         % no line under header
```

That logo will appear in the left header on *every* page.

### HTML only (fixed top banner)

After your YAML (no extra files needed), drop:

```html
<style>
.fixed-header{
  position: fixed; top:0; left:0; right:0;
  background:white; padding:5px; text-align:center;
  z-index:1000;
}
body{margin-top:70px;}  /* push content below header */
</style>
<div class="fixed-header">
  <img src="logo.png" style="height:40px;" alt="Logo"/>
</div>
```

This will pin the image at the top of *every* rendered HTML page.

---

Pick the method that fits your output type and desired placement. Let me know if you need any tweaks!

To get a logo **truly above** your title (rather than after it), you need to tell the LaTeX or HTML template to render the image **inside** the title‐making routine. Here’s how to do that in each format:

---

## PDF (`pdf_document`)

**1.** In your YAML, drop the normal `geometry:` etc., and add a custom `header-includes` block that **redefines** `\maketitle`:

```yaml
---
title: "My Report"
author: "Elliot Dean"
date:   "`r format(Sys.Date(), '%-d %B %Y')`"
output:
  pdf_document:
    latex_engine: xelatex
header-includes:
  - \usepackage{graphicx}
  - \makeatletter
  - \renewcommand{\maketitle}{
      \begin{center}
        % Logo above the title
        \includegraphics[height=1.5cm]{logo.png}\\[1em]
        {\LARGE\bfseries \@title \par}
        \vskip 0.5em
        {\large \@author \par}
        {\small  \@date \par}
        \vskip 1.5em
      \end{center}
    }
  - \makeatother
---
```

* `\renewcommand{\maketitle}{…}` replaces the default title block with one that first centers and prints your `logo.png`.
* Adjust `height=...` and vertical skips (`\\[1em]`, `\vskip`) to taste.

Now when you knit, LaTeX will run *your* `\maketitle`, logo and all, before printing the actual title text.

---

## HTML (`html_document`)

Pandoc’s default HTML template prints the `<h1>` title before your `before_body` include. To put an image above the title you can either **inject raw HTML** at the top of the body *and* hide the default title, or better—**embed the image in your YAML title** itself:

```yaml
---
title: |
  <img src="logo.png" style="height:60px;" alt="Logo"/><br/>
  My Report
author: "Elliot Dean"
date:   "`r format(Sys.Date(), '%-d %B %Y')`"
output: 
  html_document:
    df_print: paged      # optional
    includes:
      in_header: null    # we won’t use a separate header file here
---
```

* By using the **block scalar** (`|`) for `title:`, you can embed HTML.
* The `<img>` appears *in place* of the normal title, so it shows above “My Report.”
* You can still style via CSS or inline styles.

If you prefer to keep the Markdown title and just pin a logo above it on *every* page, use a fixed `<div>` in your document body:

```html
<!-- put this immediately after the YAML -->
<style>
.fixed-logo {
  position: fixed; top: 0; left: 0; right: 0;
  background: white; padding: 5px;
  text-align: center; z-index: 1000;
}
body { margin-top: 80px; }  /* adjust for logo height */
</style>
<div class="fixed-logo">
  <img src="logo.png" style="height:50px;">
</div>
```

### How to Include Time Variables in the Model

To get coefficients for your time variables, you must model the **unadjusted sale price** (`LN_PRICE`), not the time-adjusted price (`LN_TASP`). This approach measures the impact of all variables, including time, simultaneously.

```r

df_model_ready <- df_model_ready %>%
  mutate(LN_PRICE = log(saleprice))

model_with_time <- lm(LN_PRICE ~ LNSBLDSFINT + LN_LANDRATIO + GARAGE + FIREPLACE +
                        # All other property characteristics...
                        CLUSTER10 +
                        # Add the time spline variables here
                        MONTHS_6TO22 + MONTHS_23TO30,
                      data = df_model_ready)

# View the summary to see the coefficients
summary(model_with_time)
```

### Important Methodological Note

The workflow in the SPSS script you provided intentionally removes the time variables from the final model for a specific reason. [cite\_start]The goal is to create a model whose coefficients can be applied to properties that have not sold[cite: 412].

The process is:

1.  [cite\_start]**Find Time's Effect:** A preliminary model is run using the **unadjusted price** to find the coefficients for the time variables (`MONTHS_6TO22`, etc.)[cite: 383].
2.  [cite\_start]**Adjust for Time:** These coefficients (rates) are used to calculate the Time Adjusted Sale Price (`TASP`), which represents what each property would have sold for at a single point in time[cite: 416].
3.  [cite\_start]**Final Model:** The final regression is run using `LN_TASP` as the dependent variable but **excluding** the time variables[cite: 418]. This is because the effect of time has already been accounted for in the dependent variable itself.

Including time variables as predictors for `LN_TASP` would be circular and statistically problematic, as `LN_TASP` is a direct function of those same time variables.

That “rows in use has changed” error plus the follow-on “na.exclude.default(): argument ‘object’ is missing” both stem from the same root: your stepwise routine is seeing a *different* set of rows when it refits smaller models, and then you tried to call `na.exclude()` with no object. The fix is to nail down your sample **before** you call `lm()` / `step()`, and let the model’s `na.action` handle the rest. Here’s a bullet-proof recipe:

---

### 1. Identify all variables in your full model

```r
# Suppose full_model_2 was defined like this:
# full_model_2 <- lm(Y ~ X1 + X2 + X3 + X4, data = df)

# Grab the formula
f <- formula(full_model_2)

# Get the variable names out of it
vars <- all.vars(f)  
# e.g. c("Y","X1","X2","X3","X4")
```

---

### 2. Filter your data to complete cases *once*

```r
df_clean <- df[ complete.cases(df[ , vars ]), ]
nrow(df_clean)  # make sure this is > 0 and matches what SPSS reported
```

This guarantees *every* sub-model sees exactly the same rows.

---

### 3. Re-fit your full model on the clean data, with `na.action` baked in

```r
full_model_clean <- lm(
  f,
  data      = df_clean,
  na.action = na.omit   # now the model object remembers to omit NAs
)
```

You’ll never need to call `na.exclude()` manually, so you won’t get that “argument missing” error.

---

### 4. Run stepwise on the cleaned, NA-omitting model

```r
reduced_model <- stats::step(
  full_model_clean,
  direction = "backward",
  trace     = 0          # silent mode if you prefer
)
```

Since `full_model_clean` was fit on a fixed, NA-free dataset, **all** calls to `update()` inside `step()` will use the same rows, and the “number of rows has changed” error goes away.

---

### 5. (Optional) Check that every sub-model uses the same `n`

You can spot-check:

```r
nobs(full_model_clean)               # say, 120
mod2 <- update(full_model_clean, . ~ . - X3)
nobs(mod2)                           # should also be 120
```

If those match, you’re safe to proceed.

---

#### TL;DR

1. **Pre-filter** your data once with `complete.cases()` on *all* model vars.
2. **Refit** with `lm(..., na.action = na.omit)`.
3. **Call** `step()` on that model.

That will eliminate both the row-count mismatch error and the stray `na.exclude()` invocation.

## 2) Color points by “most to least significant”

You need a **numeric score** to represent significance. Common choices:

* If you have **p-values** → use `-log10(p)` (larger = more significant).
* If you have **t/z stats or effects** → use `abs(stat)` (larger = more significant).
* If you have **residuals** → use `abs(standardized_residual)`.

Examples:

```r
# A) p-values present
df <- df %>% mutate(sig = -log10(p_value))  # higher = more significant

# B) t-stat present
df <- df %>% mutate(sig = abs(t_stat))      # higher = more significant

# C) make & use standardized residuals
#   lm_fit <- lm(y ~ x, data = df)
#   df <- df %>% mutate(sig = abs(rstandard(lm_fit)))
```

Then map `sig` to color:

```r
library(ggplot2)

  geom_point() +
  scale_colour_viridis_c(option = "C", direction = 1, name = "Significance") +
  theme_minimal()
```

Tip: If you want “most significant = hottest color”, keep the default direction for `-log10(p)` or `abs(stat)`. If your score is reversed, add `direction = -1`.

## Bonus: fold both into your `graphing()` helper

```r
library(ggplot2)
library(rlang)
library(dplyr)
library(scales)

graphing <- function(data, x, y,
                     z = NULL,                  # optional categorical mapping
                     label = NULL,              # column to print by each point
                     label_digits = 2,          # how many decimals on labels
                     signif_by = NULL,          # numeric column to color by
                     signif_transform = c("auto","neglog10","abs","identity"),
                     color = "black",
                     xlab = NULL, ylab = NULL, title = NULL) {

  signif_transform <- match.arg(signif_transform)

  xq <- enquo(x); yq <- enquo(y)
  zq <- enquo(z); lq <- enquo(label); sq <- enquo(signif_by)

  use_z <- !quo_is_null(zq)
  use_l <- !quo_is_null(lq)
  use_s <- !quo_is_null(sq)

  df <- data

  # format labels if requested
  if (use_l) {
    acc <- 10^(-label_digits)
    df <- df %>% mutate(.label_fmt = number(!!lq, accuracy = acc))
  }

  # build significance score if requested
  if (use_s) {
    df <- df %>%
      mutate(
        .sig_raw = !!sq,
        .sig = dplyr::case_when(
          signif_transform == "neglog10" ~ -log10(.sig_raw),
          signif_transform == "abs"      ~ abs(.sig_raw),
          TRUE                           ~ .sig_raw   # "auto" or "identity"
        )
      )
    # auto: if it *looks* like p-values in (0,1], switch to -log10
    if (signif_transform == "auto") {
      rng <- range(df$.sig_raw, na.rm = TRUE)
      if (rng[1] >= 0 && rng[2] <= 1) df$.sig <- -log10(df$.sig_raw)
    }
  }

  # choose mapping: significance overrides z if both given
  aes_base <- if (use_s) {
    aes(x = !!xq, y = !!yq, colour = .sig)
  } else if (use_z) {
    aes(x = !!xq, y = !!yq, colour = !!zq)
  } else {
    aes(x = !!xq, y = !!yq)
  }

  p <- ggplot(df, aes_base) +
    geom_point() +
    { if (use_z || use_s) stat_smooth(method = "lm", se = FALSE)
      else                 stat_smooth(method = "lm", se = FALSE, colour = color) } +
    { if (use_l) geom_text(aes(label = .label_fmt), size = 2.5, vjust = -0.6, check_overlap = TRUE) } +
    labs(x = xlab, y = ylab, title = title) +
    theme_minimal()

  if (use_s) {
    p <- p + scale_colour_viridis_c(name = "Significance")
  }

  p
}
```

**Numeric drift** (KS / PSI); **categorical drift** (chi-sq):

```r
# KS for numeric predictors
ks_num <- map_dfr(num_vars, ~{
  xA <- A[[.x]]; xB <- B[[.x]]
  tibble(var = .x, ks = suppressWarnings(ks.test(xA, xB)$statistic))
})

# PSI helper
psi_vec <- function(a, b, bins = 10) {
  qa <- quantile(a, probs = seq(0,1,length.out=bins+1), na.rm=TRUE)
  cutA <- cut(a, qa, include.lowest=TRUE); cutB <- cut(b, qa, include.lowest=TRUE)
  pA <- prop.table(table(cutA)); pB <- prop.table(table(cutB))
  sum((pA - pB) * log((pA + 1e-12)/(pB + 1e-12)))
}
psi_num <- map_dfr(num_vars, ~tibble(var=.x, psi = psi_vec(A[[.x]], B[[.x]])))

# Categorical drift
chisq_cat <- map_dfr(cats, ~{
  t <- table(A[[.x]], B[[.x]])
  tibble(var = .x, chisq_p = suppressWarnings(chisq.test(t)$p.value))
})

ks_num %>% arrange(desc(ks))
psi_num %>% arrange(desc(psi))
chisq_cat %>% arrange(chisq_p)
```

## Why (R^2) differs a lot across periods (common culprits)

* **Target variance** differs (range restriction); same MAE, worse (R^2).
* **Feature drift** (mix of makes/models/channels changed).
* **Price/promo regimes** changed (different elasticities).
* **New categorical levels** unseen in the earlier period.
* **Measurement/units** changed (e.g., gross vs net, pre/post tax).
* **Seasonality** or macro shocks (holidays, lockdowns) missing from the model.

### Minimal “triage” checklist

1. Align schema/units; deflate prices.
2. Look at target SD per period.
3. Compare top correlations & PSI; flag biggest drifts.
4. Fit pooled model with period interactions; run Chow/Wald test.
5. Cross-predict A→B and B→A.
6. Add seasonality/promo features; consider log transforms.
7. If still unstable, move to elastic net or mixed effects.

Yes — you can save **multiple functions** together, and whether you use **`.RData`** or **`.rds`** mainly depends on how you want to load them later.

## The two formats (what’s different)

### `.rds` (recommended most of the time)

* Saves **one R object** (but that object can be a *list* containing many functions).
* You load it with `readRDS()` and **assign it to a name**.
* Nice because it **doesn’t dump objects into your global environment** unexpectedly.

### `.RData` / `.rda`

* Saves **one or more objects by name** into a file.
* You load it with `load()` and the objects reappear in your environment **with their original names** (or into a specified environment).
* Good for “workspace-like” bundles, but easier to accidentally overwrite objects.

---

## Option A: Save multiple functions in one `.rds` (best practice)

### 1) Bundle functions into a list

```r
funs <- list(
  model_metrics_A = model_metrics_A,
  coef_table      = coef_table
)
```

### 2) Save and load

```r
saveRDS(funs, file = "my_functions.rds")

funs2 <- readRDS("my_functions.rds")
funs2$model_metrics_A(mod_base)
funs2$coef_table(mod_base)
```

### If you want them as “regular” functions after loading

```r
list2env(readRDS("my_functions.rds"), envir = .GlobalEnv)
# Now you can call:
model_metrics_A(mod_base)
coef_table(mod_base)
```

(If you prefer not to pollute `.GlobalEnv`, you can load them into a dedicated environment—see below.)

---

## Option B: Save multiple functions in an `.RData` file

```r
save(model_metrics_A, coef_table, file = "my_functions.RData")
```

Load them back:

```r
load("my_functions.RData")
model_metrics_A(mod_base)
coef_table(mod_base)
```

### Safer `.RData` loading: load into an environment

This avoids clobbering objects in your global env:

```r
fn_env <- new.env(parent = emptyenv())
load("my_functions.RData", envir = fn_env)

fn_env$model_metrics_A(mod_base)
fn_env$coef_table(mod_base)
```

---

## Which should you use?

* Use **`.rds`** if you want *explicit* loading and fewer side effects (my default recommendation).
* Use **`.RData`** if you want to save multiple named objects and restore them by name (or into an env).

---

## One more practical tip (for long-term projects)

If these are functions you’ll use repeatedly, the most robust workflow is to put them in a plain text file like `R/functions.R` and then:

```r
source("R/functions.R")
```

or, even better, make a tiny internal package. But for quick sharing and reuse, `.rds`/`.RData` is totally fine.

The most reliable way is to **stop letting models “reach back” into whatever `df` happens to be at the moment**. Instead, make each model use a **frozen modeling frame** (one dataframe per model), and keep that dataframe *attached to the model* (either as an object you save, or inside the model itself via `model.frame()`/recipes). Then you can always verify `nobs()`, row IDs, and column set.

Here are practical patterns that work well in your exact situation (lots of mutates, filters, stepwise, refits, mgcv, dummies, etc.).

---

## 1) Always create a stable `row_id` once, early

This is the backbone. Do it right after import, before any filtering.

```r
df <- df %>%
  dplyr::mutate(row_id = dplyr::row_number())
```

Now you can always map “model rows” back to the original dataset.

## 3) Make a tiny “model registry” so you always know what used what

This is the easiest way to keep track as your script grows.

```r
model_registry <- new.env(parent = emptyenv())

register_model <- function(name, model, data) {
  model_registry[[name]] <- list(
    model = model,
    data  = data,
    nobs  = nobs(model),
    rows  = model.frame(model)$row_id,
    vars  = names(model.frame(model))
  )
  invisible(model_registry[[name]])
}
```

## 4) Always verify a model is using the intended dataframe

Here’s a check function that tells you if the model rows match the dataframe rows (by `row_id`) and whether required variables are present.

```r
check_model_data <- function(model, data, id = "row_id", strict = TRUE) {
  mf <- model.frame(model)

  if (!id %in% names(mf) || !id %in% names(data)) {
    stop("Both model.frame(model) and data must contain '", id, "'.")
  }

  used_ids <- mf[[id]]
  data_ids <- data[[id]]

  missing_in_data <- setdiff(used_ids, data_ids)
  extra_in_data   <- setdiff(data_ids, used_ids)

  vars_needed <- setdiff(names(mf), c("(Intercept)"))
  vars_missing <- setdiff(vars_needed, names(data))

  msg <- list(
    nobs_model = nrow(mf),
    nrow_data  = nrow(data),
    missing_ids_in_data = missing_in_data,
    extra_ids_in_data   = extra_in_data,
    missing_vars_in_data = vars_missing
  )

  if (strict) {
    if (length(missing_in_data) > 0) stop("Some model row_id values not in data.")
    if (length(vars_missing) > 0) stop("Data missing variables used by model: ", paste(vars_missing, collapse=", "))
  }

  msg
}
```

Usage:

```r
check_model_data(mod_ln_tasp, df_ln_tasp)
```

If you accidentally pass the wrong dataframe later, you’ll catch it immediately.

## 6) Make a standard “fit wrapper” that freezes data automatically

If you want one reusable approach:

```r
fit_lm_frozen <- function(formula, data, id = "row_id") {
  if (!id %in% names(data)) {
    data <- data %>% dplyr::mutate(!!id := dplyr::row_number())
  }

  mf <- model.frame(formula, data = data, na.action = na.omit)

  # Fit on the frozen model frame (so step/update always stable)
  mod <- lm(formula, data = mf)

  list(
    model = mod,
    data  = mf,
    row_id = mf[[id]]
  )
}
```

Usage:

```r
fit1 <- fit_lm_frozen(formula_ln_tasp, df)
mod_ln_tasp <- fit1$model
df_ln_tasp  <- fit1$data
```

Now `mod_ln_tasp` and `df_ln_tasp` are forever aligned.

## 7) Naming convention that prevents confusion

Adopt a consistent scheme:

* `df_raw` = loaded file, minimal cleaning
* `df_feat` = engineered variables (logs, dummies, month bins)
* `df_<modelname>` = frozen modeling dataset
* `mod_<modelname>_full`, `mod_<modelname>_back` etc.

Example:

* `df_feat`
* `df_ln_price`
* `mod_ln_price_full`, `mod_ln_price_back`
* `df_ln_tasp`
* `mod_ln_tasp_full`, `mod_ln_tasp_back`

And never overwrite those objects. If you change something, make `df_ln_tasp_v2`.

1. Add `row_id` once to your main dataframe.
2. For every model:

   * or at least save `df_used <- model.frame(mod)`
4. For any later diagnostics/refits:

   * use `model.frame(mod)` (not the global df)

Below are the safest patterns I use in modeling workflows.

---

## 1) Add a variable computed on a filtered df back to the original df

### Case A — `df_in` is just a filtered subset of rows of `df`

Example: `df_in <- df %>% filter(GOOD == 1)` and you computed `ratio2` per-row.

**Best practice:** make sure there’s a stable row identifier (e.g., `SALEID`) and join it back.

```r
library(dplyr)

df_in <- df %>%
  filter(GOOD == 1) %>%
  mutate(ratio2 = pred_price / saleprice) %>%
  select(SALEID, ratio2)

df <- df %>%
  left_join(df_in, by = "SALEID")
```

✅ This will add `ratio2` to matching rows and leave others as `NA`.
✅ Safe even if the row order changes.

**If you don’t have a key**, but `df_in` came directly from `df` and row order is intact, you can do row-index assignment — but it’s less safe:

```r
idx <- which(df$GOOD == 1)
df$ratio2 <- NA_real_
df$ratio2[idx] <- df_in$ratio2
```

I’d avoid this unless you’re sure the rows haven’t been re-ordered.

---

### Case B — `df_in` has fewer rows because you aggregated

Example: you computed `ratio2` by `month_key` or by `zip`, etc.
Then you must join back using that grouping key.

```r
ratio_by_zip <- df %>%
  filter(GOOD == 1) %>%
  group_by(ZIP) %>%
  summarise(ratio2 = mean(pred_price / saleprice, na.rm = TRUE), .groups = "drop")

df <- df %>% left_join(ratio_by_zip, by = "ZIP")
```

## 2) Create a “safe” new dataframe to store model outputs / derived variables

This is often the cleanest approach: keep your raw `df` untouched, and maintain a **model_outputs table** keyed by ID.

### Pattern: a “results ledger” (wide form)

```r
library(dplyr)

results <- df %>%
  distinct(SALEID)   # start minimal, just the key

# After model 1:
pred1 <- tibble(SALEID = df$SALEID, pred_m1 = pred_price_m1)
results <- results %>% left_join(pred1, by = "SALEID")

# After model 2:
pred2 <- tibble(SALEID = df$SALEID, pred_m2 = pred_price_m2)
results <- results %>% left_join(pred2, by = "SALEID")
```

Then you can compute ratios safely without touching `df`:

```r
results <- results %>%
  left_join(df %>% select(SALEID, saleprice), by = "SALEID") %>%
  mutate(ratio_m1 = pred_m1 / saleprice,
         ratio_m2 = pred_m2 / saleprice)
```

This makes it trivial to keep predictions/residuals from multiple models aligned.

---

### Pattern: long/tidy form (best for many models)

If you’ll have lots of models, store predictions in long format:

```r
library(tidyr)

pred_long <- bind_rows(
  tibble(SALEID = df$SALEID, model = "m1", pred = pred_price_m1),
  tibble(SALEID = df$SALEID, model = "m2", pred = pred_price_m2)
)

# join saleprice once
pred_long <- pred_long %>%
  left_join(df %>% select(SALEID, saleprice), by = "SALEID") %>%
  mutate(ratio = pred / saleprice)
```

Retrieve all rows for a model:

```r
pred_long %>% filter(model == "m2")
```

Pivot wide if needed:

```r
pred_long %>% select(SALEID, model, pred) %>%
  pivot_wider(names_from = model, values_from = pred)
```
